# Current editor source attachment

`POST /api/v1/assistant/chat` accepts optional `editor_source: {language: "c" | "asm", content: string}`. Old clients can omit it. `GET /api/v1/assistant/status` adds `editor_source_supported: true`. Deploy this backend before enabling the FE #18 source workflow; old servers reject unknown fields, and the frontend explicitly blocks source requests until support is advertised.

The frontend captures only the active C editor or editable ASM source when a question is sent. Compiled assembly from a previous build is not substituted. Attachment defaults on and can be disabled. Blank code is omitted; more than 12,000 Unicode code points / 48,000 UTF-8 bytes is rejected without silent truncation. The source is a separate field, not appended repeatedly to conversation history. Prior assistant answers may still quote code in retained conversation history when current attachment is off.

Authentication and the existing per-question quota remain in place. The classifier receives at most 4,000 source characters marked as untrusted analysis data. Only ALLOW invokes the answer provider, which receives the full accepted source as a separate user-data message before the latest question. Code comments cannot change policy. The server adds a content digest and labels the source as an unverified editor draft. It never claims that the draft produced an attached execution snapshot. Existing snapshot ownership/version checks still apply independently.

Source text is not added to application logs, persistence or usage telemetry. SOLID receives it for inference under the service's data-handling terms; this is not a promise of provider-side non-retention. The frontend shows the language/size and current source attachment state for each question. Existing SSE delta/done/error events remain unchanged. The question label records the requested attachment, not proof that a classifier-approved answer was generated.

Validation: frontend unit/transport tests and browser fixture exercise C, edits, ASM, disabling source and rejecting unsupported servers. Backend regression tests cover schemas, gate routing, untrusted message placement, size bounds and quota once. Three opt-in actual-model cases were added to `scripts.evaluate_assistant_context.py` (C, ASM, comment injection); they still require live-model evaluation. No merge or deployment is performed by this change.
