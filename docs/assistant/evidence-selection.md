# 질문별 근거 선택과 실행 답변 검증

PR #14의 백엔드 변경이다. 프론트·DB·배포 변경은 없다. 요청 바디, 인증·실행 소유권·버전 검증, SSE 이벤트와 채팅당 한도 예약 1회는 유지한다. 전체 실행 이력을 자동 조회하지 않는다.

## 처리 순서

1. 인증, 실행 참조 검증, 요청 한도 예약을 기존 순서대로 처리한다.
2. SOLID가 최신 질문의 decision/topics를 판별한다. 서버가 형식을 검증하고 ALLOW일 때만 답변 호출을 시작한다.
3. 실행 자료가 있는 실행 질문에는 서버가 검증한 사실 목록을 만든다. SOLID에는 목록과 최신 질문을 보내고 **사실 ID만 선택**하게 한다.
4. 선택 결과 전체를 받은 뒤 ID·형식·개수·중복·모순을 서버에서 검증한다. 문장과 수치는 서버가 작성한다. 모델의 자유 문장이나 계산값은 이 경로에서 표시하지 않는다.
5. 일반 코드/정적 흐름 설명과 실행 미첨부 질문은 기존 자유 형식 스트리밍을 사용한다. 이 경로의 문장 정확성은 강제 검증하지 않는다.

판별과 답변은 계속 두 번의 모델 호출이다. 근거 검사에 별도 모델을 호출하지 않는다. timeout·취소·upstream 동시성 제한은 기존 경로를 공유한다.

## 최신 질문과 최근 대화

판별에는 최신 질문을 전부 보낸다. 120자 이하이며 '그럼/왜/더 설명/요약/예시/then/why' 등 후속 표현이 있는 질문만 최근 사용자 메시지 최대 4개를 참고한다(각 마지막 1,000자, 합계 4,000자). 이전 AI 답변은 판별에서 제외한다. 이 규칙은 입력을 선별할 뿐 ALLOW를 강제하지 않는다. 장문 후속 질문이나 표지 없는 생략 질문은 오차단될 수 있다.

판별에는 실행 모드/사이클과 코드 언어/문자 수만 추가한다. 첨부 원문은 전달하지 않는다. 질문 본문에 붙인 코드는 그대로 질문에 포함된다. 답변 프롬프트들은 공통 DOMAIN_POLICY를 사용한다.

## 실행 답변의 근거 목록

| 유형 | 서버가 허용하는 내용 |
| --- | --- |
| registers | 질문에 이름이 나온 레지스터의 현재 값; x0 불변 원리; 이전 값/명령어 없이 변화 원인을 검증할 수 없다는 안내 |
| stack | sp/s0 값과 바이트 차이; 검증된 오프셋 주소. 차이를 프레임 크기로 단정하지 않음 |
| memory | 사용자가 선택한 메모리 값, 이름을 지정한 레지스터, 검증된 주소 연산 |
| hazards | 선택 사이클 스톨/포워딩/플러시의 true/false/미상 구분, load-use 원인 코드, 검증 가능한 포워딩 경로 |
| cpi | 선택/전체를 분리한 서버 계산과 일관성 검사; 개선 후 실행이 없으면 개선 CPI는 미상 |
| identity / flow | 원문·실행 동일성 미검증; 실제 반복 횟수/초기화 이력 미상 |
| mapping | 일반적인 C→ASM 변환 원리. 실제 문장별 매핑 검증은 지원하지 않는다는 안내 |

기존 `execution_evidence`가 내부 자료를 선별하지만, 실행 답변의 외부 모델에는 그 전체나 튜터 원문을 그대로 보내지 않는다. `claims.py`의 허용 목록을 통과한 값·문장·근거 종류만 보낸다. 선택 사이클의 원시 설명 문자열이나 코드 주석을 서버 문장에 끼워 넣지 않는다. 포워딩 경로는 발생 플래그와 동일 길이의 from/to/register/value 배열을 확인하고 알려진 단계·피연산자·레지스터·RV32 값만 허용한다. 지원하지 않는 경로 표현은 생략한다.

**기능상의 제한:** 실제 C·ASM 소스 매핑, 임의 명령어별 변화 원인, 복합 실행 해설을 자유롭게 작성하던 범위가 줄어든다. 근거 목록에 없는 질문은 자료 요청으로 끝날 수 있다. 질문과 관련 없는 유효 ID를 고르는 의미적 오류까지 서버가 검증하는 것은 아니다. 일반 코드 설명이나 실행 미첨부 질문은 이 보호 범위 밖이다.

## 출력 검사와 계산

내부 응답은 `{"format":"text","facts":["cpi_selected"]}` 형식이다. JSON 요청이면 format=json을 허용하며, 최종 키/값도 서버가 정한다. 기본 근거는 최대 3개, JSON·상세 요청은 최대 8개다. 임의 문장·추가 필드·알 수 없는 ID·중복 키/ID·타입 오류·8,192자 초과·상충하는 JSON 값은 통과하지 않는다.

`SOLID_LLM_CLASSIFICATION_FORMAT=json_schema`이면 판별뿐 아니라 이 선택에도 JSON Schema를 적용한다. none이어도 서버 검증은 항상 유지한다. 실행 선택은 temperature=0이다. 모델이 완성된 형식을 어기거나 빈 선택을 보내면 고정 확인 불가 안내를 delta→done으로 반환한다. 출력이 잘리거나 연결이 끊기면 기존 error로 종료하고 부분 선택은 표시하지 않는다. 재시도하거나 자유 형식 답변으로 우회하지 않는다.

CPI는 같은 범위의 cycles/retired를 비교한다. 누락·0분모·음수·타입 오류·NaN/Infinity·선택 누적값이 전체보다 큰 경우는 확정하지 않는다. RV32 주소 계산은 허용된 레지스터 +/- 정수만 다루며 임의 수식 실행이나 wraparound를 하지 않는다. 서버 사실을 사용하더라도 제공된 실행 데이터 자체의 정확성과 모든 교육 설명의 정확성을 보장하지는 않는다.

## 프론트 인수인계

새 요청 필드나 이벤트는 없다. 실행 답변은 검증 후 **delta 한 개 → done**으로 나올 수 있다. 첫 delta 전에 연결/keepalive만 와도 로딩을 유지하고, 중지는 기존 연결 취소로 처리한다. `done.context`는 기존 전체 실행 참조이며 `done.usage`는 답변 단계 비용이다. 내부 사실 ID를 프론트에서 해석하지 않는다. 일반 코드 답변은 기존 점진적 스트리밍이 유지된다. 이번 작업에서는 프론트를 변경하지 않았다.

관측에는 기존 판별/답변 토큰 합계와 함께 `assistant_answer_validation`의 requestId 및 validated/empty/invalid/incomplete 결과만 추가한다. 선택 ID, 실행 값, 대화 원문, 키나 공급자 오류 본문은 신규 저장하지 않는다.

## 재현

```sh
python scripts/compare_assistant_quality.py --source-root /path/to/source-export --arm candidate --output /tmp/quality.json
python -m scripts.evaluate_assistant_context --cases tests/fixtures/assistant_claim_cases.json
```

합성 질문만 사용하며 실제 호출 비용이 든다. `--review`는 합성 답변을 검토용으로 출력하되 파일에는 저장하지 않는다. metadata에는 프롬프트/fixture 해시, 사실 비교, 판정, 길이, 첫 delta 지연, 사용량만 남긴다. [최종 결과와 남은 문제](evaluations/2026-11-13-validated-claims.md)를 함께 확인한다.
