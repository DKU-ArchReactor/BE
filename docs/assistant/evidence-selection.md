# 질문별 실행 근거 선별과 서버 계산

PR #14 내부 변경이다. 프론트 요청 바디, 인증·소유권·실행 버전 검증, SSE와 요청당 1회 한도 예약은 유지한다. 전체 이력을 자동 조회하는 기능은 추가하지 않는다. 병합·배포는 별도다.

## 처리 순서

1. 기존 인증·한도 및 실행 참조 검증으로 제한된 스냅샷을 얻는다.
2. 기존 SOLID 판별 호출 한 번에서 decision과 topics를 받는다. 서버가 엄격히 검증하며 실패 시 error로 종료한다. 요청에서 topics를 직접 지정할 수 없다.
3. ALLOW일 때만 주제별 필드를 합쳐 답변 근거를 구성한다. 모든 유형을 고르면 전체 허용 필드의 합집합까지만 가능하며, 기존 크기·소유권 제한을 넘길 수 없다.
4. 서버에서 수치를 검증하고 공통 도메인 정책과 간결한 답변 지침을 적용한다.
5. 기존 SOLID 스트림을 delta/done으로 반환한다. done.context는 기존 전체 실행 참조를 유지한다. 모델에 보여 주는 참조에는 불필요한 ELF/결과 해시를 제외한다.

## 전송 범위

| 유형 | 실행 근거 | 작성 원문 |
| --- | --- | --- |
| code / flow | 동일성 미검증·과거 이력 없음만; 실행 ID/사이클·레지스터 없음 | 제공 |
| mapping | 선택 단계 명령어·해당 명령어 튜터 해설 | 제공 |
| registers | 선택 레지스터 값·단계·명령어 튜터 해설 | 제공 |
| memory | 선택 레지스터·명시적으로 선택한 메모리·단계·명령어 해설·주소 연산 | 제공 |
| stack | sp/s0·단계·명령어 해설·주소 연산 | 제공 |
| hazards | 선택 사이클 이벤트·단계·사이클 튜터 해설 | 제공 |
| cpi | 선택/전체 CPI 검증값·선택 이벤트 | 제외 |
| identity | 선택 실행 참조·동일성 미검증·과거 이력 없음 | 제외 |
| service / concept | 동일성 미검증·과거 이력 없음만 | 제외 |

복합 주제는 합집합이다. 예를 들어 registers+stack이면 전체 선택 레지스터가 포함될 수 있다. 분류가 잘못되면 필요한 자료가 빠지거나 불필요한 허용 자료가 포함될 수 있다. 이 선별은 권한 검증을 대신하지 않으며 LLM 분류의 정확성을 보장하지 않는다.

판별 단계에는 현재 질문, 제한된 최근 대화, 실행 모드/사이클, 코드의 언어/문자 수만 보낸다. 별도 첨부 코드 원문은 판별에 보내지 않는다. 질문 본문에 직접 붙여 넣은 코드는 질문 일부로 남는다.
답변의 최근 대화도 최대 6개, 메시지당 마지막 1,000자·합계 4,000자 이내이며 검증되지 않은 JSON 데이터로 제공한다. 이전 AI 답변을 실행 사실로 채택하지 않도록 지시하지만 모델이 이를 항상 지킨다고 보장하지 않는다.

## 계산 규칙

- 선택 CPI는 같은 시점의 elapsed_cycles/accumulated_instructions, 전체 CPI는 total_cycles/instructions_executed로 각각 검증한다.
- 정상은 verified, 누락은 missing, 완료 명령 0은 undefined, 음수·잘못된 타입·NaN/Infinity·수치 불일치는 inconsistent다. 검증되지 않은 CPI는 null이다.
- 선택 누적 횟수가 전체 요약보다 크면 범위 모순으로 표시하고 두 CPI를 확정하지 않는다.
- 주소는 RV32의 0~0xffffffff 범위에서 처리한다. sp/s0 차이는 바이트 차이일 뿐 프레임 크기가 아니다.
- 명시적인 `sp`, `s0`, `fp`, `x0`~`x31`의 `+/- 정수`만 지원한다. 정수는 10진 또는 16진이며 질문당 최대 8개 연산이다. 음수/범위 밖 결과는 유효 주소로 내보내지 않는다. 임의 수식 실행, 메모리 조회, 주소 wraparound는 없다.
- 검증값을 모델에 제공할 뿐 자유 형식 답변의 모든 수치를 사후 강제 검증하는 기능은 아니다. 모델이 값을 무시하거나 잘못 해석할 가능성은 실제 평가로 계속 확인해야 한다.

## 프론트 인수인계

새 API 호출·요청 필드·SSE 이벤트는 없다. 기존 원문/실행 첨부 UI를 그대로 사용할 수 있다. topics나 검증값을 브라우저에서 만들어 보내지 않는다. 실행 ID·선택 사이클은 기존 done.context를 사용한다. 판별에 자료 선택이 포함되지만 호출 수는 그대로다.

## 평가 재현

`tests/fixtures/assistant_quality_cases.json`은 정상 5개와 의도적인 CPI 모순 1개다. 정상 사례에서 잘못 복사됐던 전체 요약을 제거했다. 전체/선택 수치 분리·범위 모순은 단위 테스트로도 검사한다.

```sh
python scripts/compare_assistant_quality.py --source-root /path/to/source-export --arm candidate --output /tmp/quality-metadata.json
```

같은 실행 환경에서 source-root만 바꾸어 각 버전을 별도 프로세스로 평가한다. 평가기는 공통으로 사용하며 모델·프롬프트·fixture 해시와 길이/시간/사용량/판정을 저장한다. 외부 호출 비용이 발생하므로 명시적으로 실행한다. `--review`는 합성 응답을 수동 검토용으로 출력하며 집계 파일에는 저장하지 않는다. 실제 사용자 대화나 비밀값을 평가 입력/출력으로 사용하지 않는다.

정형 평가와 8개 버튼의 개별/연속 대화, 상세 요청을 구분한다. 정형 JSON 추출 성공이 자연어 설명의 정확성을 보장하지 않으므로 실제 모델의 남은 오류도 보고서에 기록한다.
