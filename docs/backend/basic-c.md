# 기초 C 지원 범위

RV32IM C 컴파일은 `basic-c-v1` 정책을 적용한다. 인자 없는 `int main(void)`
하나만 허용하며 기존 `int main()` 표기도 허용한다. main 내부의 32비트 이하 정수형
지역 변수, 고정 크기 배열, 연산, 조건문, 반복문을 사용할 수 있다.
`#include`/`#define` 등 전처리 지시문, 함수 호출(간접 호출·재귀 포함), 추가 함수,
전역 선언, extern/static 선언, 포인터·사용자 정의 자료형, 실수형·long long,
가변 길이 배열, 인라인 어셈블리는 지원하지 않는다.

입력값은 지역 변수·배열에 직접 지정한다. 결과는 변수·배열에 저장하거나 정수로
반환하며, return은 콘솔 출력이 아니다. 계산 과정 관찰에는 `-O0`을 권장한다.
ASM과 native 프로파일의 기존 동작은 유지한다.

## API와 AI 예제

- `POST /api/v1/build/validate-c`, 본문 `{"content":"int main(void){return 0;}"}`:
  인증·DB·스토리지·컴파일러 없이 검사한다. 응답은
  `{"policy":"basic-c-v1","valid":true,"diagnostics":[]}`이다.
  입력은 UTF-8 65,535바이트까지이며, 진단에는 `code`, `message`, 1부터 시작하는
  `line`, `column`이 포함된다. 문법 범위 통과는 컴파일·실행 성공 보장이 아니다.
- `/compile`의 직접 입력과 저장 파일 경로 모두 같은 검사를 거친다. 실패 시
  기존 HTTP 201 및 `status: failed` 계약을 유지하고 `log`와 `diagnostics`를 제공한다.
  컴파일러를 실행하거나 산출물을 업로드하거나 시뮬레이션 토큰을 발급하지 않는다.
- AI 시스템 프롬프트도 같은 범위를 지시한다. 프론트는 AI의 C 코드 적용 전에
  `/validate-c`를 호출하며 검사 실패/통신 오류 시 편집기를 교체하지 않는다.
  기존 코드에 대한 설명 자체는 제한하지 않는다.

검사는 외부 전처리기를 실행하지 않고 주석·문자열과 줄 연결을 구분한 후
pycparser AST를 검사한다. 이는 학습용 문법 제한이며 실행 보안 샌드박스가 아니다.
백엔드 PR을 먼저 배포한 뒤 프론트를 배포한다. 예전 백엔드에서는 검증 API가 없어
새 프론트의 AI C 코드 적용이 차단되지만 수동 편집은 가능하다.
