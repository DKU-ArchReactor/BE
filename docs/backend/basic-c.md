# 기초 C 지원 범위

RV32IM C 컴파일은 `basic-c-v1` 정책을 적용한다. 인자 없는 `int main(void)`
하나만 허용하며 기존 `int main()` 표기도 허용한다. 32비트 이하 정수형 지역·전역 변수,
고정 크기 배열과 main 내부의 연산, 조건문, 반복문을 사용할 수 있다.
지역·전역 변수와 배열의 `volatile`/`const` 한정자를 허용하며, `static` 전역 변수도 허용한다.
전역 변수의 초기화 유무와 main 앞뒤 선언 위치에 관계없이 같은 자료형·초기화식 검사를 적용한다.
`#include <stdlib.h>`와 포인터 및 `malloc`·`calloc`·`realloc`·`free` 직접 호출을 허용한다.
다른 헤더/전처리 지시문, 그 외 함수 호출(간접 호출·재귀 포함), 추가 함수,
extern 선언, static 지역 선언, 사용자 정의 자료형, 실수형·long long,
가변 길이 배열, 인라인 어셈블리는 지원하지 않는다.

입력값은 지역·전역 변수나 배열에 직접 지정한다. 결과는 변수·배열에 저장하거나 정수로
반환하며, return은 콘솔 출력이 아니다. 계산 과정 관찰에는 `-O0`을 권장한다.
ASM과 native 프로파일의 기존 동작은 유지한다.

## API와 AI 예제

- `POST /api/v1/build/validate-c`, 본문 `{"content":"int main(void){return 0;}"}`:
  인증·DB·스토리지·컴파일러 없이 검사한다. 응답은
  `{"policy":"basic-c-v1","valid":true,"diagnostics":[]}`이다.
  입력은 UTF-8 65,535바이트까지이며, 진단에는 `code`, `message`, 1부터 시작하는
  `line`, `column`이 포함된다. 문법 범위 통과는 컴파일·실행 성공 보장이 아니다.
- `/compile`의 직접 입력과 저장 파일 경로 모두 같은 검사를 거친다. 실패 시
  기존 HTTP 201 및 `status: failed` 계약을 유지하고 `log`와 `diagnostics`를 제공한다.
  컴파일러를 실행하거나 산출물을 업로드하거나 시뮬레이션 토큰을 발급하지 않는다.
- AI 시스템 프롬프트도 같은 범위를 지시한다. 프론트는 AI의 C 코드 적용 전에
  `/validate-c`를 호출하며 검사 실패/통신 오류 시 편집기를 교체하지 않는다.
  기존 코드에 대한 설명 자체는 제한하지 않는다.

검사는 외부 전처리기를 실행하지 않고 주석·문자열과 줄 연결을 구분한 후
pycparser AST를 검사한다. 이는 학습용 문법 제한이며 실행 보안 샌드박스가 아니다.
백엔드 PR을 먼저 배포한 뒤 프론트를 배포한다. 예전 백엔드에서는 검증 API가 없어
새 프론트의 AI C 코드 적용이 차단되지만 수동 편집은 가능하다.

## 동적 메모리 런타임

- 제한된 `stdlib.h`는 `size_t`, `NULL` 및 네 할당 함수만 제공한다. 컴파일 시 신뢰된 헤더를
  C 소스에만 자동 포함하며 사용자 소스 행 번호는 유지한다. 헤더를 생략한 코드도 동작한다.
- 런타임은 RV32IM으로 별도 컴파일·링크한다. 사용하지 않는 할당 함수와 내부 상태는 링크 시 제거한다.
- 힙은 `0x10004000`부터 4 KiB인 CORE의 가상 메모리 범위를 사용하며 16바이트 정렬을 보장한다.
  첫 블록의 최대 페이로드는 4,080바이트다. 메타데이터·분할 상태에 따라 작아질 수 있다.
  링커 절대 심볼로 시작 주소를 제공하며, CORE가 거부하는 추가 ELF 섹션을 만들지 않는다.
  초기화되지 않은 가상 메모리 읽기는 0이며, allocator가 블록 메타데이터를 초기화한다.
- 최초 적합 블록을 분할하고, `free`가 인접 빈 블록을 합쳐 재사용한다. `calloc`은 곱셈
  오버플로를 검사하고 0으로 초기화한다. `realloc` 성장 실패 시 기존 블록/내용을 보존한다.
- `malloc(0)`/0 크기 `calloc`은 NULL, `free(NULL)`은 무동작,
  `realloc(NULL, n)`은 malloc과 동일, `realloc(p, 0)`은 해제 후 NULL이다.
- 할당 실패는 NULL로 반환한다. 잘못된 포인터 해제·이중 해제·범위 밖 접근은 지원하지 않는다.
  런타임 내부 명령도 시뮬레이션 클록에 포함되므로 작은 배열/반복으로 예제를 구성한다.

## 내부 코드 메타데이터

빌드 분석의 각 명령어에 `function`과 선택적 `runtime_context`를 제공함. objdump의 함수 심볼과 소스 파일이 번들 `allocator.c`의 할당 함수 또는 `start.S`의 `_start`로 함께 확인될 때만 함수 역할 설명을 추가함. 사용자 C 줄 매핑은 그대로 유지하며, 출처가 불명확한 명령어를 내부 코드로 추정하지 않음. 이 정보는 함수 전체의 역할이며 개별 명령어의 실행 관측 결과가 아님.
